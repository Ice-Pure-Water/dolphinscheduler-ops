### API 能力如何映射为 skill 完整功能

目标 OpenAPI 的覆盖面大于 MCP Pilot 宣称的常用工具集，也大于本地 CLI。Skill 应将这些接口映射到统一操作阶段，而不是机械暴露全部写 API：

- **身份和权限面**：登录/SSO、Token、用户/租户、项目与资源授权。登录凭据或 Token 的创建、更新、吊销和权限授予属于安全敏感写操作；默认只核验当前会话身份与可见范围，不代替管理员授予权限。
- **资产面**：项目、项目参数/偏好、工作流定义/版本/Task/关系、资源、数据源、环境、集群、队列、Worker Group、任务组、告警配置、动态 Task 类型。先读取依赖和引用，再做最小字段修改；连接测试、库表列探查只读但可能泄露 schema，应按授权范围使用。
- **运行面**：调度预览及生命周期、工作流/任务实例查询、启动/批量启动、任务执行、停止/暂停/恢复/重跑/补数、Task 强制成功/savepoint/缓存清理。运行控制和批量接口一律按高影响操作管理；先计算目标实例集合和日期/任务范围，禁止用模糊筛选直接批量写入。
- **可观测面**：日志详情/下载、Master/Worker/DB 状态、审计日志、状态统计、数据质量规则与结果。结果需要分页、时间窗和脱敏；日志下载、审计读取需遵守最小必要范围。
- **扩展与兼容面**：V1/V2 重复路由、Azure 云接口、K8S namespace、UI 插件、动态任务类型、血缘和数据质量。不要假定 V1/V2 语义相同，也不要因接口存在便推断部署启用了对应插件或账号具备权限。

**调用前生成 operation 清单**：每个具体 API 记录 method/path/operationId、参数位置/必填字段、响应结构、是否分页、写副作用、权限要求及目标版本；对无白名单说明的 POST/GET 写副作用保持未知并停止。API 的 HTTP 方法不能单独证明读写属性（例如 GET 也可能产生副作用）。不要通过 OpenAPI 原始请求暴露口令字段。

## 能力目录

| 能力域 | 可复用的操作流程 | 当前本地 CLI | 边界 |
|---|---|---|---|
| 连接与发现 | 校验服务根地址 → 安全登录 → 读取 OpenAPI → 列项目并解析唯一 project code | `ds_ops.mjs` 需要 `DS_URL/DS_USER/DS_PASSWORD`，固定 DS 3.2.0 | 不读取用户权限外资源；不把 HTTP 200 当作登录/业务成功 |
| 工作流/DAG | 查定义、版本、任务、依赖、子流程、资源引用；差异预览；保存后结构与画布复查 | `inspect`、`show-sql`、`update-definition`、`update-task`、`update-workflow-info`、`release` | 创建、克隆、历史版本回滚不在 CLI 完整支持范围；MCP 实际支持时仍按写门禁操作 |
| 调度 | 查 schedule；核对 Cron、时区、告警及状态；创建 OFFLINE 后再按授权上线 | `inspect`、`create-schedule`、`online-schedule`、`offline-schedule` | 修改/删除/补数能力不可由现有 CLI 概述推断；上线和补数需精确授权 |
| 实例与任务 | 查状态、分页日志、识别失败节点、追踪父子工作流 | `inspect-instance` 只覆盖已实现诊断；其他以 MCP 工具盘点为准 | 暂停/恢复/停止/重跑/失败节点重跑/删除/强制成功/跳过节点不可由本地 CLI 全覆盖；操作影响运行状态或业务数据 |
| 资源中心 | 列目录/文件、读取内容、核对引用；在明确资源根目录下预览更新 | 当前 CLI 不提供全套资源管理 | 创建、上传、重命名、覆盖、删除均需路径白名单和用户授权；删除前检查全部引用 |
| 监控与日志 | 查询最近失败和运行中的实例；逐任务检查状态；分页拉取日志并脱敏 | 以本地 inspect 能力为限 | 限制日志页数和总量；不把日志/SQL 参数原样送入模型或输出 |
| 数据源/租户/用户/告警 | 仅查询当前账号可访问的元数据和权限配置 | 无通用 CLI 覆盖声明 | 改权限、租户、数据源口令、告警配置需单独授权；秘密字段永不读回/回显 |
| Raw API | 仅用于已确认有必要且 skill/工具白名单没有覆盖的接口 | 不提供通用 raw 写入 | 默认禁止任意 raw POST/PUT/DELETE；只允许经过目标 OpenAPI 核对的最小只读请求，不能把 raw endpoint 当绕过保护的后门 |

## 通用任务流程

### 1. 登录和对象定位

从已配置的受保护 MCP connection 或环境变量读取凭据，不向用户索取明文密码。确认服务地址、版本、认证方式和 MCP 工具 schema；读取 `/v3/api-docs` 并比对 operationId。项目、工作流、任务、调度、实例、资源逐层解析唯一 code/id。遇到重名、权限不足、分页缺失、版本漂移或 API 未知时停止写操作。

### 2. 诊断失败

先列出有限时间窗内相关工作流实例，再读取目标实例和任务实例；顺着失败 task code 查日志，若为子流程则追到子实例。对照定义版本、运行日期、参数来源、worker group、外部作业状态和目标数据证据。报告事实/推测/未确认点、最小建议动作和副作用。诊断请求默认不改变 DS 状态。

### 3. 创建/修改工作流

创建前查询同名对象、项目权限和所需资源；以完整 DAG 草案呈现 Task 类型/参数、依赖边、全局参数、租户、worker group、资源及子流程引用。修改前保存当前定义、版本、任务参数、关系和发布/调度状态。生成字段级 diff 与 dry-run；写入后回读版本、任务和边并运行结构预检。任何结构缺失或画布无法检查时，不报告验收通过。涉及在线定义时必须遵循 OFFLINE 生命周期及 schedule 状态恢复流程。

### 4. 调度与补数

创建/修改前展示 Cron、时区、开始结束时间、告警组、失败策略和在线状态。上线前确保定义已发布且调度字段回读正确。补数前展示日期闭区间、串并行顺序、起始/结束任务、下游传播范围、预计实例量和重复写风险；用户授权覆盖具体范围后再执行。完成后逐日核对实例，不以 API 接受请求作为补数完成。

### 5. 实例处置

暂停/恢复/停止/重跑/失败节点重跑/删除/强制成功/跳过节点前，核对精确实例与 task code、当前状态、外部计算任务、已产生数据和幂等性。强制成功/跳过失败会绕开正常检查，默认不主动建议执行；仅在用户明确指定并给出业务验收措施时执行。写后回读实例和任务状态，并进行数据验收。

### 6. 资源操作

读取资源前核对完整路径和用途。写入/覆盖先校验目标资源 ID、引用关系、内容差异、编码/大小限制和恢复副本；创建必须使用请求明确给出的根目录。删除前扫描定义引用；无法证明无引用则停止。写后按 ID 与完整路径回读内容摘要。

## MCP 工具调用规则

- 用 `tools/list`（或宿主提供的等效工具目录）确认工具及参数，不假定工具名固定。优先使用结构化、窄权限操作；不使用批量 DAG patch 隐式更改未展示字段。
- 每个写工具调用前显示对象身份、变更范围和 dry-run 结果；授权必须精确覆盖该写动作。会话授权不自动延伸到其他工作流、日期或环境。
- 设置分页、日志、回溯时间窗和批量条数上限。页重复、总量不符或接口返回字段截断时标记结果不完整并停止。
- 对 API 失败只允许一次状态回读以判断是否部分提交；不得盲目重发创建、补数、通知或运行请求。
- MCP 返回的 `next_action` 等建议只是提示，需由本 skill 重新做状态、影响面和授权检查后才能执行。
- 不将社区工具声称的 multi-tenant、token auth、版本兼容等宣传视为本地事实；在服务端、连接器版本和配置中分别验证。

## 能力状态报告格式

执行任务时标明：`可用工具/CLI`、`目标 DS 版本`、`目标对象 code/id`、`只读或写操作`、`已核实状态`、`证据缺口`、`授权范围`、`写后验收结果`。没有实际 MCP/API 连接时只提供操作方案，不声称已登录、已保存或已修复。
